# Internationalisation (M1-18)

Status: **core built 2026-10-07** (`feat/M1-18-i18n-core`); screens migrate namespace by namespace.

## Decisions
- Languages: **English (default, fallback) + Slovenian**; more later (global market). David, 2026-10-02.
- Language = the user's explicit choice on this device (SecureStore `petprep.language`) → else the
  device's first supported preferred language → else English.
- Switch: compact `EN | SL` on the start screen (before login — a child may not read the device
  language) and "Jezik / Language" card in the parent Nadzor tab. Per device, not per account.
- The app sends `Accept-Language: en-GB | sl-SI` on every API request; server texts (push, errors)
  follow it (backend part of M1-18).
- Native permission texts (iOS Info.plist) are localised via `mobile/locales/<lang>.json`
  (`app.json` → `locales`); `expo-localization` plugin declares `supportedLocales` (Android 13+ /
  iOS per-app language). **Needs a new native build.**

## How it works (mobile)
- `mobile/src/i18n/` — `index.ts` (i18next instance, `t`, `setLanguage`, `loadSavedLanguage`,
  `currentLanguage[Tag]`), `language.ts` (pure helpers), `resources.ts` (namespaces),
  `strings.ts` (`strings()` view), `locales/<lang>/<namespace>.json`.
- Namespaces: `common, auth, child, behaviour, training, contract, parent, family, account, pet,
  push, paywall`. English is the reference; key types come from `locales/en/*.json`.
- `__tests__/parity.test.ts` fails when a language misses a key, has an extra key, a different
  `{{placeholder}}`, an empty string, or plural forms that don't match its CLDR categories
  (en `_one/_other`, sl `_one/_two/_few/_other`).
- Jest runs with a Slovenian test device (`jest.setup.ts` mocks `expo-localization`), so existing
  tests keep asserting Slovenian copy; English is tested with `i18n.changeLanguage('en')`
  (reset to `sl` in `afterEach`).

## Migrating a string table
The app keeps its per-screen `*_STRINGS` objects, now backed by i18next:

```ts
// before
export const CHILD_PIN_STRINGS = {
  title: 'Vpiši svojo kodo',
  rateLimited: (time: string) => `Preveč poskusov. Počakaj še ${time}, potem poskusi znova.`,
} as const;

// after — locales/sl/auth.json + locales/en/auth.json: { "pin": { "title": "…", "rateLimited": "… {{time}} …" } }
export const CHILD_PIN_STRINGS = strings('auth', 'pin', {
  rateLimited: (time: string) => t('auth:pin.rateLimited', { time }),
});
```

Rules:
1. Plain strings → JSON leaves (read lazily through the `strings()` proxy). Functions → `{{vars}}`
   in JSON + an explicit function in the third argument (nested objects allowed:
   `{ errors: { tooMany: (n) => t(…) } }`).
2. Hand-written Slovenian plurals (`n === 1 ? … : n === 2 ? …`) → i18next plurals:
   `"dogs_one": "{{count}} pes", "dogs_two": "{{count}} psa", "dogs_few": "{{count}} psi",
   "dogs_other": "{{count}} psov"` (sl) and `"dogs_one" / "dogs_other"` (en); call
   `t('family:x.dogs', { count })`.
3. Never put a translated value in a module-level constant or in `useMemo` without the language
   as a dependency. Screens/components that host language-dependent memoised text call
   `useTranslation()`.
4. Inline JSX literals and `accessibilityLabel`s count too. Brand names (PetPrep) stay.
5. Dates / times: format with `currentLanguageTag()` when using `Intl`; hand-built Slovenian
   phrases ("jutri ob 18:00") become keys with placeholders.
6. Comparisons against server values must not use translated text (use codes).
7. English copy: natural, short, kind for the child (2nd person, "you"), polite and clear for the
   parent. Slovenian copy stays exactly as it was (tests rely on it).
