## 2. Data model (PostgreSQL)

**Family model (M2-01, ADR-012).** A family has several parents and several children; each child cares for its own pet or several children share one pet. Ownership and authorization go through `families` / `family_user` / `pet_caretakers`; `users.parent_id`, `users.timezone` (of a parent) and `pets.user_id` are **deprecated mirrors** kept in sync for current app builds (model hooks on `User` / `Pet` / `QuietHours` map writes of the old columns into the family model; removal = follow-up M2-01b).

**families** — `id, timezone (IANA string(64), default Europe/Ljubljana), timestamps`. The **family timezone** for every wall-clock rule (`User::familyTimezone()` / `Pet::familyTimezone()` read it; before M2-01 it was the parent's `users.timezone`, which is still mirrored for every parent). The pet, not the family, is the billing unit (49.99 € per pet, BUSINESS_MODEL).

**family_user** — `id, family_id → families (**restrict**), user_id → users (unique, cascade: one family per user), role (parent|child, CHECK), timestamps`. Index `(family_id, role)`.

**family_invites** — second-parent invite codes: `id, family_id, created_by → users, code (unique, 8 chars from ABCDEFGHJKMNPQRSTUVWXYZ23456789), expires_at (24 h), used_at, used_by → users, timestamps`. Single use; a new code from the same parent expires their previous unused one.

**pet_caretakers** — `id, pet_id → pets (cascade), user_id → users (the child; **nullable, SET NULL since PR #29** — null = a deleted child's tombstone), started_at / ended_at (nullable, PR #29: caretaker history — a deleted child's row on a shared pet is kept with user_id null, started_at = their start (contract / birth), ended_at = deletion time; `CareScoreService` counts it as a sharer of every routine that opened while it was caring, so the remaining children's past fair share doesn't change; `PetCaretaker::active()` / `Pet::caretakers()` / `caretakerRows()` / recipients / dashboard lists use active rows only), pet_is_active (copy of pets.is_active maintained by the triggers `pet_caretakers_copy_pet_is_active` (BEFORE INSERT/UPDATE) and `pets_sync_caretaker_is_active` (AFTER UPDATE OF is_active on pets) — never written from PHP), requires_contract (true = must sign their own contract before acting; false only for rows backfilled from pets born before contracts — grandfathered), timestamps`. Unique `(pet_id, user_id)`; **partial unique index `pet_caretakers_one_active_pet_per_child (user_id) WHERE pet_is_active AND ended_at IS NULL`** (ended rows ignored since PR #29) = a child cares for at most one active pet (MVP choice, pending David). Every pet has ≥ 1 caretaker (service rule; `Pet::created` adds `pets.user_id` when that user is a child — legacy pets owned by a parent account have none and are logged by the migration). The trigger reads the pet `FOR SHARE`.

**Deletes never cascade from a family into child data** (PR #14 review): `pets.family_id`, `family_user.family_id`, `quiet_hours.family_id` are `ON DELETE RESTRICT`; only `family_invites` cascade. Lock order for family writes: parent user row → child user row → family row (`PairingService::pairChild`, `FamilyInviteService::joinFamily`).

**Account deletion (M2-08) = `AccountDeletionService` only** (API + Filament; Filament has no plain user delete any more). Immediate, irreversible, one `DB::transaction(…, 3)` (retried on deadlock / serialization failure) that first locks **every parent row of the family (id order), every child row (id order), the family row, then the pet rows** (PR #29). A full-family purge also deletes **orphaned legacy child accounts** (role child, `parent_id` → one of its parents, no family); a leaving parent's legacy pets in **other** families are deleted (ledger detach + files), never left to the cascade. Password confirmation: `confirmPassword($user, $password, scope)` — 5 **failed** attempts / 15 min per user, separate scopes `account` / `child` (429 `too_many_attempts` + `Retry-After`; a success clears the counter). **Watch the cascading deprecated mirrors:** `users.parent_id`, `pets.user_id` and `quiet_hours.parent_id` are `ON DELETE CASCADE` — deleting a user without re-pointing them first deletes children / pets / quiet hours. So: a parent leaving a family that keeps another parent hands the family's quiet-hours row, the children's `parent_id` and legacy parent-owned pets to that parent; a deleted child's shared pet gets `pets.user_id` = the next caretaker; users outside the purge whose `parent_id` points into it get `parent_id = null`. Pets are deleted with a query-builder delete (no model events) after `AiSpendLedger::detachPets()`; their rows cascade (activities, contracts incl. signatures, caretakers, per-child steps, walks, routines, status periods, hygiene events, PINs, media slots) and the files go in the queued `DeletePetMediaFiles` job **after commit**. Deleted child on a shared pet: `activities_log.actor_user_id` / `pet_daily_routines.actor_user_id` → null (FK `SET NULL`; the rows keep counting for the pet), the caretaker row becomes a **tombstone** (user_id null, started_at kept, ended_at = now — PR #29), the child's contract and `pet_daily_steps` rows go (today's steps stay in `pets.daily_step_count` and are attributed to the primary caretaker on the next sync). Also deleted per user: Sanctum tokens, `sessions`, `password_reset_tokens` (by e-mail). One audit log line per deletion (`Account deletion: family_deleted | parent_removed | parent_deleted | child_deleted` with family id + counts, no names / e-mails / user ids). Superadmins can't be deleted (API 403 `superadmin_protected`; Filament refuses a family with a superadmin member).

**pet_daily_steps** — each child's own steps per family-local day on a pet: `id, pet_id, user_id, local_date, steps, last_sync_at (anti-cheat reference per child), timestamps`. Unique `(pet_id, user_id, local_date)`. The pet's `daily_step_count` (→ energy, daily walk) = sum over its caretakers; steps the pet has that no row explains (from before M2-01) belong to the primary caretaker.

**users** — `id, name (a child's **nickname**, ≤ 30 chars via the API; a parent's display name, ≤ 60 at sign-up), birth_year (smallint, nullable, CHECK 1900–2100 — the only age datum of a child, M2-02), email (**nullable since M2-02**, unique — PostgreSQL treats NULLs as distinct; stored lower case by `/api/register`, compared case-insensitively by register + login + Filament via `lower(email)`; functional index `users_email_lower_unique` (UNIQUE) — or `users_email_lower_index` (plain, colliding ids logged) if legacy rows already differ only in case, PR #25), email_verified_at (nullable, not used yet — M2-10b), terms_accepted_at (nullable, **M2-10a**: when a self-registered parent accepted the terms of use + privacy policy; null for seeded / admin parents and every child), terms_version (string(32), nullable, PR #25: which legal-text version was accepted, from `config/legal.php`; never returned by the API), password (**nullable since M2-02**; PIN-only child profiles have neither), role (parent|child, CHECK), timezone (IANA string(64), NOT NULL, default `Europe/Ljubljana`; for a parent a mirror of `families.timezone` since M2-01), is_superadmin, parent_id → users (cascade; **deprecated** — the parent who paired the child), pairing_pin(6), pin_expires_at, pairing_pet_id → pets (nullable, null on delete: the child PIN joins this existing pet; null = the PIN creates a new pet), revenuecat_id (unique), timestamps`. Indexes: `parent_id`, `pairing_pin`. All timestamps stay UTC (`APP_TIMEZONE=UTC`).

**pets** — `id, user_id → users (child; **deprecated** = primary caretaker, the child the pet was created for), family_id → families (NOT NULL, **restrict**), breed_type (mutt|border_collie, CHECK), pet_dna JSONB (GIN), current_video_url, hunger_level, thirst_level, energy_level, hygiene_level (double precision 0–100, CHECK; Eloquent cast `float`; every API/broadcast/Filament output rounds half up to int via `Pet::displayMetric()` / `Pet::attributesToArray()`), daily_step_count, last_step_reset_at (start of the current family-local step day; set at birth), last_step_sync_at (device time of the last accepted step sync — anti-cheat reference, cleared at midnight), last_decay_at (decay clock, nullable; set at birth — on create for a born pet, at contract signing for a paired one; backfilled to migration time), frozen_at (start of the current hard stop / illness freeze, null otherwise), hygiene_scheduled_through (date: last family-local day whose hygiene events exist), born_at (**nullable, no default since M1-07b**: null = unborn — paired, waiting for the contract; set to the signing moment by `POST /api/child/contract`; pets created before M1-07b kept theirs = grandfathered as born, even without a contract), is_active, pet_state (CHECK: idle|sleeping|low_energy|hungry|sick|playing), illness_until (null again after recovery), walk_illness_due_at (planned start of a missed-walk illness — daily walk rule), escalation_level (0–3), {hunger,thirst,hygiene}_zero_since (neglect clocks), energy_zero_since (unused since the daily walk rule, always null), is_game_over, is_hard_stopped, certificate_eligible, timestamps`. Index `(user_id, is_active)`.

**activities_log** — `id, pet_id → pets, actor_user_id → users (nullable, null on delete — the child who did it, M2-01; null for system rows: escalation), activity_type (fed_pet|watered_pet|walked_pet|cleaned_poop|ignored_warning|signed_contract, CHECK), value int nullable, created_at`. Indexes `(pet_id, created_at)`, `(actor_user_id, created_at)`. Backfill: child-action rows got `pets.user_id`, `ignored_warning` rows stay null. `value` conventions for `ignored_warning`: 30 = phase 1, 10 = phase 2, 0 = phase 3, −1 = illness, −2 = game over; `walked_pet`: one row per day when a step sync first reaches the daily goal, value = the day's steps (not one row per sync — the dashboard counts a walk once); `fed_pet` / `watered_pet`: the hunger / thirst % shown just before the action; `cleaned_poop`, `signed_contract`: null. `fed_pet` / `watered_pet` rows are also the source of truth for "already fed in this window" / "water used today" (M1-07).

**breed_configs** — every tunable game number (M1-06), mutt | border collie: `breed_slug (mutt | border-collie), daily_steps_required (4000 | 10000), hunger_decay_rate (8 | 12 %/h), thirst_decay_rate (10 | 15 %/h, CHECK ≥ 0), poops_per_day (1 | 2, CHECK 0–10), feed_windows (jsonb list of family-local [start, end) "HH:MM" pairs, default [["06:00","10:00"],["17:00","21:00"]], CHECK array), water_times_per_day (3), water_min_gap_minutes (180), premium_unlock`. Column defaults = mutt values (backfill for existing rows). `BreedConfigsSeeder` upserts by slug and runs on every production deploy (overwrites Filament edits — open question). Feed windows and water limits are enforced by the child API (M1-07). Note the slug uses a hyphen and the enum uses an underscore — `BreedType::slug()` maps them.

**pet_hygiene_events** (M1-05) — `id, pet_id → pets (cascade), local_date (family-local day), scheduled_at (UTC), status (pending|applied|skipped, CHECK), resolved_at, cleaned_at, timestamps`. Unique `(pet_id, scheduled_at)`, index `(pet_id, status, scheduled_at)`. `applied` = hygiene dropped to 0 at `scheduled_at`; `skipped` = fell into a freeze / before birth / into quiet hours changed later; `cleaned_at` = the clean that took care of it.

**pet_daily_walks** (daily walk rule, David 2026-10-03) — `id, pet_id → pets (cascade), local_date (family-local day), steps, goal (breed daily_steps_required that day), achieved (steps ≥ goal), birth_day, illness_due_at (planned illness start when the day had no walk at all), illness_started_at (when it actually started), illness_skipped_at (planned illness dropped: pet frozen when due, or evaluated only after its 12 h were over), timestamps`. Unique `(pet_id, local_date)`. One row per closed day; raw material for the parent dashboard (M2-05).

**pet_status_periods** (M2-06) — when a pet could not be cared for: `id, pet_id → pets (cascade), kind (hard_stop|illness|inactive, CHECK), started_at, ended_at (null = still going on; CHECK ≥ started_at), timestamps`. Index `(pet_id, started_at)`. Written by `PetStatusPeriodService` from the `Pet` `created` / `updated` model hooks (inside the writer's transaction) — so the parent's hard-stop toggle, `EscalationService` (illness `[frozen_at, illness_until)`, game over → `inactive`) and Filament edits all record history; quiet writes (`saveQuietly`) never change these flags except the end of an illness, whose end is stored up front. An admin who clears `illness_until` early cuts the running period at that moment; re-activation closes `inactive` and resets the ledger pointer. Backfill (migration `2026_10_05_120000`): one 12 h illness per `ignored_warning` −1 row (start = the walk row's `illness_started_at` within the 12 h before, else the row time), the current hard stop from `frozen_at`, current inactivity from the latest −2 row.

**pet_daily_routines** (M2-06) — the routine ledger of **closed** family-local days, one row per expected routine: `id, pet_id → pets (cascade), local_date, routine_type (feed|water|clean|walk, CHECK), slot (n-th routine of that type that day), opens_at, due_at (UTC), status (done|missed, CHECK), done_at, actor_user_id → users (null on delete; the child who did it), steps / goal (walk only), timestamps`. Unique `(pet_id, local_date, routine_type, slot)` (insert-or-ignore → idempotent), index `(actor_user_id, local_date)`. Rows are never recomputed: changing quiet hours / feed windows later does not rewrite history. **pets.routines_closed_through** (date, last closed day) / **pets.routines_next_close_at** (when the tick looks again; null = out of play and fully closed) are the close pointer — hidden from every JSON (`Pet::$hidden`).

**pet_contracts** (M1-07; signing an unborn pet's contract births it — M1-07b) — `id, pet_id → pets (cascade), user_id → users (the child), signature_format (svg_path|png, CHECK), signature text (SVG path data ≤ 20,000 chars, or base64 PNG ≤ 100 KB decoded, no data-URI prefix; hidden from serialization), signed_at (server time), timestamps`. **Unique `(pet_id, user_id)` since M2-01**: one contract per caretaker child; the first one births the pet, a later caretaker's only unlocks that child; the same child signing again → 409.

**pet_media** (M4-03 / M4-05, replaces `pet_media_jobs`) — one **slot** per `(pet_id, kind, state)` (unique index `NULLS NOT DISTINCT`): `kind image` (reference image, `state` NULL) or `kind video` with `state` ∈ `PetStateEnum` (CHECK). Columns: `profile` (config/media.php key, `legacy` = a pre-M4-05 fal URL that was only downloaded), `status (pending|running|ready|failed)`, `generation` (+1 on every regenerate; part of the file name), `source_generation` (videos: the image generation they were made from — older → regenerated after a new image), `attempts`, `request_id` (unique; fal queue id of the current video generation — webhooks are accepted only for these), `source_url` (allowlisted fal.media result URL, server side only), `storage_path` (last stored file on the `pet_media` disk — stays servable while a newer generation runs), `bytes, mime, duration_seconds`, `cost_usd` (estimated spend of all generations = sum of counted ledger rows), `error_reason` (`AiCallFailure` CHECK) / `error`, `completed_at`. Rows cascade with the pet; files are deleted by the queued `DeletePetMediaFiles` job dispatched **after commit** (from `Pet::deleted` and from `AccountDeletionService`; idempotent, skips pet ids that still exist — M2-08). Migration `2026_10_07_120000`: `pet_media_jobs` rows → `pet_media` (pending → running with the same request id, completed-but-never-downloaded → failed), table dropped; reversible.

`pets.media_status` — `disabled | pending | ready | failed` (reference image lifecycle; since M4-05 `ready` = **stored on our disk**, not just generated). `pets.current_video_url` is no longer written (legacy column; the API derives it from `pet_media`). `pets.pet_dna.reference_image_url` keeps the fal URL server side only (debug / free re-download), never in an API response. `pets.media_error` (M4-07, hidden from every API) — why the reference image is missing: `budget_daily | budget_monthly | fal_balance | http_error | …` (CHECK = `AiCallFailure`), null when fine.

`pets.pet_dna` (jsonb) — **v1** (pets born before M4-08, or `AI_PET_DNA_VERSION=1`): `{seed, visual_traits, prompt_anchor, reference_image_url}`; never rewritten. **v2** (M4-08, `PetDnaService`): `{version: 2, seed, salt, attempt, breed, traits {size, build, coat_length, coat_color, coat_pattern, markings, ear_carriage, eye_color, tail}, trait_fingerprint (sha256 of breed + sorted traits), appearance_verified (false until M1-19), prompt, negative_prompt, prompt_anchor (= prompt), visual_traits (= traits), reference_image_url}`. `seed` = crc32(`petprep-pet:{id}:{salt}`) (32-bit, passed to fal); traits are sampled deterministically from `config/breed_appearance.php` (weights, `only_with` conditions); within a **family** no two v2 pets of the same breed share a `trait_fingerprint` (up to 25 attempts; the pairing transaction holds the family row lock). The prompt is built only from breed + traits + fixed photo style — never from names or other personal data.

**ai_spend_ledger** (M4-07) — one row per fal.ai call: `purpose (lab|reference_image|state_video), profile, endpoint, unit (image|megapixel|second), units, cost_usd (ESTIMATE from config/media.php list prices), status (reserved|committed|void), error_reason, request_id, pet_id → pets (null on delete), pet_media_id → pet_media (null on delete, M4-03), media_lab_result_id → media_lab_results (null on delete), timestamps`. **Rows outlive pets (M2-08):** `AiSpendLedger::detachPets($petIds)` nulls `pet_id` + `pet_media_id` **before** any pet delete (`Pet::deleting` hook, `AccountDeletionService`) — left to the two `ON DELETE SET NULL` FKs, a row linked to both the pet and its slot fails the DELETE (PostgreSQL re-checks `pet_media_id` while setting `pet_id` null, after the slot is gone); the cost stays for accounting. Caps count `reserved + committed`, in **two separate budgets** (PR #22 review): production (`reference_image`, `state_video`) vs `AI_DAILY_BUDGET_USD` / `AI_MONTHLY_BUDGET_USD`, and `lab` vs `AI_LAB_DAILY_USD` / `AI_LAB_MONTHLY_USD` (refusal `budget_lab`) — the lab can never starve new pets. **Settlement:** `void` only when nothing reached fal (cURL 5/6/7/35/51/58/60, or 28 "Resolving / Connection timed out") or fal answered 4xx/5xx; a timeout / reset **after sending** → `committed` with `error_reason = http_error` (fal may still run and bill it); a 2xx queue answer without `request_id` → `committed` + `invalid_response`.

**media_lab_runs / media_lab_results** (M4-02 AI Lab, admin only, no child data) — run: `user_id (superadmin), kind (image|video), breed, fixed_traits, samples, profiles[], pet_state, source_result_id (image animated by a video run), estimated_cost_usd`; result: `kind, profile, endpoint, sample_index, seed, traits, prompt, negative_prompt, params (exact fal input), source_image_url, request_id (unique, fal queue), status_url / response_url (queue.fal.run only), status (queued|running|completed|failed|unknown — `unknown` = video submit sent but the answer was lost: no `request_id`, nothing to poll, cost kept), error_reason, error, result_url (*.fal.media only), latency_ms, estimated_cost_usd (charged estimate; 0 when refused)`.

**quiet_hours** — one row per **family** (M2-01): `parent_id → users (unique; the parent who created it — handed to a remaining parent when its creator moves to another family), family_id → families (unique, restrict), school_start/end, bedtime_start/end (time), is_active`. Any parent of the family reads / edits it; `Pet::quietHours()` reads by `family_id`.

**child_login_pins** (M2-02) — one-time PINs a parent issues **for a specific child profile**: `id, family_id → families (cascade), child_user_id → users (cascade), created_by → users (null on delete), pet_id → pets (nullable, cascade: join target), pin_hash (HMAC-SHA256 of the 6 digits with `APP_KEY` — the PIN itself is never stored), expires_at (15 min), consumed_at, revoked_at, timestamps`. **Partial unique index `child_login_pins_open_pin_unique (pin_hash) WHERE consumed_at IS NULL AND revoked_at IS NULL`** = the lookup key of `POST /api/child/pin-login`; generation retries on a collision (savepoint) and revokes expired-but-open rows with the same hash first. A new PIN for a child revokes that child's open one. Old rows are not pruned yet (debt). The legacy parent-row PIN (`users.pairing_pin`, `POST /api/child/pair`) is separate.

**personal_access_tokens** (Sanctum) — every token issued since M2-02 has exactly one ability: `["parent"]` or `["child"]` (`TokenAbility::forUser`); tokens from before have `["*"]` and keep working. A child keeps at most **3** tokens (devices): each PIN login deletes the oldest beyond 3.

Laravel default tables: `password_reset_tokens, sessions, cache, jobs, failed_jobs, personal_access_tokens`.

**Authorization layers (M2-03).** (1) `auth:sanctum`; (2) **token ability** on the route group — `/api/parent/*` requires `ability:parent`, `/api/child/*` (except the public `pin-login`) `ability:child` (Sanctum `CheckForAnyAbility`, aliases in `bootstrap/app.php`; a missing ability → 403); legacy `["*"]` tokens pass every ability check; (3) **policies** (role + family: `UserPolicy@manageFamily` / `@manageChild`, `PetPolicy@useChildApi` / `act` / `listen` / `manage`) — they still separate the roles for `*` tokens. Shared routes (`/api/user`, `/api/logout`, `/api/broadcasting/auth`) accept any ability. Tests: `actingAs($user, 'sanctum')` attaches an in-memory token with the user's role ability (`tests/TestCase.php`), `actingAsWithAbilities()` for anything else.

**Child API contract (M1-07).** Every child endpoint: guest → 401, parent → 403 (ability or `PetPolicy`), child without a pet → 404 `{reason: "no_pet"}`. The child's pet = the pet they care for (`pet_caretakers`, M2-01: active, else latest); every applied action stores the child in `activities_log.actor_user_id`. Action responses always carry `state` (the same object as `GET /api/child/pet`), so the app can update its cache without a second call:
- 200 `{status, …, state}` — `accepted` (applied, one `PetUpdated` with the activity type as `event_type`) or `unchanged` / `capped` / `rejected` / `stale` (steps);
- 422 `{message, status: "refused", reason, next_allowed_at|null, state}` — a game rule (`CareRefusal`); not Laravel's validation shape (that one has `errors`);
- 409 — contract already signed (same body as 422);
- 423 `{message, status: "locked", reason: game_over|inactive|hard_stopped|contract_required|ill, locked_until|null, state}` — priority game over › inactive › hard stop › contract required › illness. `contract_required` (M1-07b) = the pet is unborn, **or (M2-01) this child joined a shared pet and hasn't signed their own contract** — evaluated per child (`Pet::actionLockReasonFor($child)`), the other caretakers keep playing: every action except `POST /api/child/contract` is refused; the parent's pause and an inactive session win over it (signing is refused then too). An unborn pet can't be ill or game over.

`state` (`ChildPetStateResource`, all instants ISO 8601 with the family offset, e.g. `2026-10-04T17:00:00+02:00`):
`pet {id, breed_type, born_at (null while unborn), awaiting_contract (M2-01: **this child** must sign — pet unborn or own contract missing), caretakers_count, virtual_age_months, hunger_level, thirst_level, energy_level, hygiene_level (displayed ints), pet_state, escalation_level, needs_cleaning, is_active, is_hard_stopped, is_ill, illness_until, is_game_over, certificate_eligible, current_video_url, media_status, reference_image_url, media}` — **M4-05:** `media {status: disabled|pending|failed|partial|ready, reference_image_url, videos {state: url} (always a JSON object, only stored videos), current_video_url (video of `pet_state`, fallback `idle`, else null), states (entitled video states, idle first), expires_at}` with our signed URLs (`PetMediaPayload`); the legacy `current_video_url` / `reference_image_url` mirror `media` (never fal URLs). The same `media` object is in `PairedPetResource` (pairing / PIN login), the dashboard's legacy `pet` (+ `reference_image_url`, `media_status`) and every `family.pets[]`, and in `PetUpdated` · `lock {is_locked, reason, until}` · `timezone` · `server_time` · `feeding {windows [{start, end} "HH:MM"], current_window {start, end}|null, fed_in_current_window, can_feed, next_feed_window {start, end}|null (the current window while unused, else the next), last_fed_at}` · `water {times_per_day, min_gap_minutes, used_today, remaining_today, last_watered_at, can_water, next_allowed_at}` · `steps {steps_today (the pet's combined count = energy), my_steps_today (this child's own, M2-01), goal, energy_level}` · `contract {signed, signed_at}` (this child's contract). `can_feed` / `can_water` combine lock, mess and the window / water rules.

## 4. Game loop

`routes/console.php` schedules `pets:process-decay` every minute (`withoutOverlapping`, `runInBackground`) → `PetDecayService::processAllActivePets()` then `EscalationService::processAllActivePets()` then `RoutineLedgerService::closeDueDays()` (M2-06, end of §4). Also daily at 03:17 UTC: `pins:prune` (M2-02) deletes `child_login_pins` rows whose PIN expired more than 7 days ago (`--days=N`; every PIN expires 15 min after issue, so this covers used, revoked and unused ones).

**PetDecayService** (M1-01/M1-02, scheduler selects IDs of active, non-game-over pets): decay is a pure function of (precise stored metrics, elapsed time `last_decay_at → now`, breed config, quiet hours). `updated_at` is never used, so other writes don't eat decay; missed ticks are caught up in full (no cap).
- **Concurrency:** each pet is processed in its own `DB::transaction` from a fresh `Pet::lockForUpdate()` read (the passed model is only an ID and is synced afterwards), so a concurrent write is never overwritten by a stale copy. Other metric writers must take the same lock (`backend/CLAUDE.md`; `EditPet` does).
- First tick with `last_decay_at = null` only starts the clock.
- **Unborn pets** (`born_at` null, M1-07b) are excluded in SQL (`Pet::born()` scope) from both the decay tick and escalation, and `decayLockedPet` / `escalateLockedPet` / `DailyWalkService::closeDayIfNeeded` / `HygieneEventService::ensureScheduled|applyDue` return early for them as a second guard: no decay, no hygiene schedule, no day close, no escalation, nothing written. `Pet::giveBirth()` (called by `signContract` under the row lock) starts every clock at the signing moment; events of the birth day before that moment are skipped like any pre-birth event.
- **Frozen** while `is_hard_stopped`, ill (`illness_until` in the future), inactive or game over: metrics untouched, `last_decay_at` advanced to now (quiet write). Hard stop / illness also stamp `frozen_at`. The local midnight still closes the day while hard-stopped / ill (walk row, steps → 0) but never schedules a walk illness, and a walk illness that comes due during a freeze is dropped.
- **Illness recovery = fresh start** (David 2026-10-03, `Pet::recoverFromIllnessIfDue()`; first thing in every decay tick, escalation tick, child action and model update once `illness_until` has passed): at `illness_until` → hygiene 100 % and `hygiene_zero_since` null (the vet cleaned the dog), every other running `*_zero_since` restarts at `illness_until`, `escalation_level` 0, `illness_until` null, decay clock resumes at `illness_until`. Hunger / thirst keep their values. If a hard stop is still on, `frozen_at` = `illness_until` (the freeze continues). One `PetUpdated('metric_changed')` after commit. Fixes the illness loop (before, the clock still showed ≥ 6 h after the 12 h).
- **Thaw of a hard stop** (`Pet::applyThaw($at)`): shifts every non-null `*_zero_since` forward by `at − frozen_at` (neglect time spent frozen doesn't count), restarts the decay clock at `at`, clears `frozen_at`. `at` = now when a hard stop is lifted (`updating` hook — works without any tick during the freeze). Re-activation / undoing game over restarts the decay clock.
- The elapsed interval is split into normal vs quiet time by jumping between quiet-window boundaries (`QuietHours::segmentsBetween()` / `splitSecondsBetween()` on top of `nextBoundaryAfter()`, ≤ 4 segments per day + DST transitions). Windows are read on the **family-local clock** (M1-03): 22:00–06:00 lasts 9 h on the fall-back night and 7 h on the spring-forward night; a boundary inside the spring gap takes effect at the jump, one inside the repeated hour occurs twice. Hunger/thirst = breed rate × (normal h + 0.10 × quiet h), rates from `breed_configs.hunger_decay_rate` / `thirst_decay_rate` (M1-06).
- **Energy (M1-04) = today's walk** — not time-decayed and **not an hourly neglect metric** (no `energy_zero_since`, no phase 3 / illness / game over from energy; daily walk rule, David 2026-10-03). `DailyWalkService::closeDayIfNeeded()` runs in every tick (and in every step sync): once the family-local date differs from `last_step_reset_at` it writes one `pet_daily_walks` row for the finished day (steps, goal, achieved; `firstOrCreate` → idempotent), then `Pet::resetDailyStepsIfNewDay()` sets `daily_step_count` and `energy_level` to 0 and clears `last_step_sync_at` (local midnight, e.g. 22:00 UTC in Slovenian summer). `last_step_reset_at` is set at creation, so a newborn keeps its initial energy until its first local midnight. Energy rises only through `PetActivityService::recordSteps()`.
- **Daily walk rule:** if the finished day ended with energy **showing 0 %** (no walk at all; < 0.5 % of the goal), is not the birth day, is exactly yesterday (one midnight passed — not after a multi-day scheduler outage) and the pet is not frozen, `pets.walk_illness_due_at` = the end of the quiet stretch that contains the midnight (`DailyWalkService::endOfQuietStretch`; bedtime 22–06 → 06:00 local; bedtime directly followed by school → end of school; no quiet hours → midnight). Some steps below the goal → only `achieved = false`. The illness time is computed from the quiet hours **in force at that midnight**; a later change of quiet hours does not move an already planned walk illness.
- **Energy backfill** (migration `2026_10_03_160100`, one-off): existing pets get `energy_level = min(100, daily_step_count / goal × 100)`; pets born on the current family-local day keep their energy (birth-day grace).
- **Hygiene (M1-05)** has no gradual decay. `HygieneEventService::ensureScheduled()` creates `poops_per_day` pending events for every family-local day from the day of `last_decay_at` to today (at most 7 past days): whole minutes drawn from the day's non-quiet time, one per equal share; RNG `Xoshiro256**` seeded with sha256(app key, pet id, date) — deterministic, not predictable by clients. `applyDue()` flips every pending event with `scheduled_at ≤ now`: `applied` if it lies in (`from`, now] and isn't quiet, otherwise `skipped` (freeze ticks and thaw advance `last_decay_at`, so events during a hard stop / illness or before birth are skipped). Any applied event → hygiene 0 and `hygiene_zero_since` = the earliest applied `scheduled_at` (exact also after a scheduler gap).
- Values are clamped to 0–100, stored unrounded, and snapped to an integer when within 1e-6 (float noise). `*_zero_since` and `pet_state` use the displayed value (zero = shows 0 %, i.e. precise < 0.5). Sets `certificate_eligible` at 12 weeks.
- **Broadcast:** all tick writes are quiet; after commit the tick broadcasts one `PetUpdated('metric_changed')` only if a rounded metric, `pet_state` or `certificate_eligible` changed. A mutt broadcasts ~213× per 24 h instead of every minute.
- Verified by 24 h minute-by-minute simulations (`tests/Feature/PetDecayTest.php`): mutt hunger 0 % at exactly 750 min, thirst 600 min; BC hunger 500 min, thirst 400 min; hygiene 91 after 6 h. Identical with 5-min ticks or a 3 h scheduler gap.
- Verified 24 h simulations with events enabled (mutt + BC): hunger/thirst zero minutes unchanged (750/600, 500/400), hygiene 100 % until an applied event and 0 % after, energy 0 % at minute 900 (local midnight).
- `pet_state`: `sick` only for hygiene 0 % (and during illness); energy 0 % shows `low_energy` outside quiet hours (`sleeping` inside).
⚠️ Remaining: hunger/thirst `*_zero_since` set at tick time (not the exact crossing time) after a catch-up gap.

**PetActivityService** (M1-04/M1-05/M1-07; called by `ChildPetController` / `ChildContractController`). Each action: transaction + `lockForUpdate()`, illness recovery first if due, refused with `ActionResult::LOCKED` + `PetLockReason` while game over / inactive / hard-stopped / unborn (`contract_required`) / ill, quiet write, one `activities_log` row (created without model events), one `PetUpdated(<activity type>)` after commit. A refused or unchanged action still broadcasts one `PetUpdated('metric_changed')` if its bookkeeping (recovery, midnight, decay catch-up) changed what the child sees.
- `feed(Pet)` / `water(Pet)` (M1-07): first `PetDecayService::catchUpLocked()` — one tick under the same lock, no broadcast — so decay owed since the last tick lands on the old value, not on the new 100 %, and due hygiene events are seen. Hygiene showing 0 % → `REFUSED needs_cleaning` (PRODUCT_SPEC §8). Then `CareScheduleService` (feed windows / water limits, see below) → `REFUSED` with `next_allowed_at`, or hunger / thirst → 100 %, `*_zero_since` → null, `pet_state` re-derived (`PetDecayService::derivePetState`), `fed_pet` / `watered_pet` row with the value shown before.
- `signContract(Pet, child, format, signature)` (M1-07): one `pet_contracts` row per **(pet, child)** since M2-01 (`REFUSED contract_already_signed` → 409 for the same child; the first contract births an unborn pet, later ones only unlock that child), `signed_contract` row, `PetUpdated('signed_contract')`. Passes only the `contract_required` lock. Unborn pet (M1-07b) → `Pet::giveBirth(now)` in the same transaction / row lock: `born_at`, `last_decay_at`, `last_step_reset_at` = signed_at, metrics 100, steps 0, neglect clocks / escalation / `walk_illness_due_at` / `hygiene_scheduled_through` / `frozen_at` cleared, `pet_state` derived; still one broadcast after commit. A grandfathered (born) pet only stores the contract.
- `clean()` now also re-derives `pet_state` (no `sick` video until the next tick).

**CareScheduleService** (M1-07): pure rules on top of `breed_configs` and `activities_log`, evaluated in the family timezone. Feed windows: the breed's `feed_windows` [start, end) "HH:MM" pairs instantiated for local yesterday…+2 days (an end ≤ start runs over midnight; a time in the spring-forward gap resolves to the instant after the jump; an empty / invalid config falls back to `BreedConfig::DEFAULT_FEED_WINDOWS`, single invalid windows are ignored; the warning is logged at most once per breed per UTC day via a cache key; Filament requires ≥ 1 window and rejects overlaps on save); "already fed" = a `fed_pet` row at or after the current window's start. Water: `watered_pet` rows in [local midnight, next local midnight) (23 h / 25 h on DST days) vs `water_times_per_day`; gap = real minutes since the latest `watered_pet` row (across midnight too); `next_allowed_at` = max(gap end, next local midnight) when the day's limit is reached.
- **Actor (M2-01):** `feed/water/clean(Pet, ?User $actor)`, `recordSteps(…, ?User $actor)`, `signContract(Pet, $child, …)` — the lock is evaluated for the actor (`actionLockReasonFor`), the activity row stores `actor_user_id`; no actor (system / old callers) = the primary caretaker (`pets.user_id`). Feed windows and water limits stay **per pet** (the dog is fed once per window, whoever feeds it).
- `recordSteps(Pet, int $stepsToday, Carbon $recordedAt, ?User $actor)`: **per child** since M2-01 — `$stepsToday` is the acting child's own cumulative count in `pet_daily_steps` (idempotency and the anti-cheat reference `last_sync_at` per child); the accepted increment is added to the pet's `daily_step_count` (sum of all caretakers = the daily walk); the `walked_pet` row goes to the child whose sync crossed the goal. For one child this is identical to before: cumulative count for the family-local day, the max wins (`UNCHANGED` for repeats / lower counts). Anti-cheat: increment capped at 200 steps per minute between max(`last_step_sync_at`, local midnight) and `recordedAt` (future → now) — `CAPPED` keeps the plausible part, `REJECTED` if none; a sync dated on an earlier local day is `STALE`. Closes the previous day first (`DailyWalkService`, same as the tick). Energy = max(current, min(100, steps / `daily_steps_required` × 100)). Logs one `walked_pet` row per day, when the count first reaches the goal (value = steps). If the action itself changed nothing but closed the previous day or applied a recovery, it still broadcasts one `PetUpdated('metric_changed')` after commit.
- `clean(Pet)`: settles hygiene events already due but not yet ticked (`HygieneEventService::settleForCleaning`), stamps `cleaned_at`, hygiene → 100, `hygiene_zero_since` → null, logs `cleaned_poop`. `UNCHANGED` when already clean.

**EscalationService**: same row-lock rule as the decay tick (M1-07 review fix): the scheduler selects IDs only and each pet is re-read with `lockForUpdate()` in its own transaction; every decision uses that fresh row, so a clean / feed / hard stop committed after the scheduler's query is respected (before, a stale model could start an illness or a game over the child had just prevented). `processPetEscalation(Pet)` uses the model only for its ID and copies the result back. Each step taken emits exactly one `PetUpdated` after commit (M1-08): `soft_warning` (level 1), `critical_alert` (level 2), `parent_intervention_alarm` (level 3), `illness_triggered`, `game_over_virtual_shelter`, `escalation_reset` (metrics recovered → level 0). A tick takes at most one step per pet; no step → no event. Skips hard-stopped and ill pets entirely (M1-02 — no new escalation, illness or game over while frozen; `thawIfDue()` runs first: recovery of an expired illness, stale `frozen_at`). Neglect clocks = hunger, thirst, hygiene (**not energy**). Then: game over (hunger / thirst / hygiene 0 % ≥ 24 h → `is_active=false`, `is_game_over=true`) › illness — (a) `walk_illness_due_at` ≤ now → illness from `walk_illness_due_at` (`illness_until` = due + 12 h, `frozen_at` = due, walk row `illness_started_at`); if due + 12 h ≤ now (scheduler down) it is skipped instead (walk row `illness_skipped_at`, no recovery side effects); game over and reactivation clear a pending `walk_illness_due_at`, or (b) hygiene 0 % for ≥ 6 h **counted outside quiet hours only** (`QuietHours::splitSecondsBetween(zero_since, now)['normal']`) → `illness_until = now+12h`; state `sick`, `frozen_at` = start › matrix (lowest displayed metric ≤ 30 → level 1, ≤ 10 → level 2 — energy counts only **outside quiet hours**; hunger / thirst / hygiene 0 % ≥ 1 h → level 3). Each escalation writes an `ignored_warning` activity (`actor_user_id` null). Push jobs are commented out (none exist); recipients are resolved in one place (M2-01): `FamilyService::caretakerRecipients($pet)` (phase 1 / 2 → every caretaker child) and `FamilyService::parentRecipients($pet)` (phase 3, illness, game over → **every parent of the family**); their ids are logged with the escalation.

**Routine ledger / Care Score / traffic light (M2-06, David 2026-10-04, PRODUCT_SPEC §9/§11).** `RoutineLedgerService` derives the routines of each family-local day from existing data (no new client calls): **feed** = each breed feed window starting that day (`CareScheduleService::feedWindowsStartingOn`, same window rules as the child API; done = a `fed_pet` row in [start, end); a window entirely inside quiet hours is not expected); **water** = `round_half_up(water_times_per_day × in-play non-quiet seconds / non-quiet seconds of the day)` refills (birth, hard stop, vet, game over pro-rated), done = that day's `watered_pet` rows in order, the rest missed at day end; **clean** = each `applied` hygiene event, done when `cleaned_at` ≤ event + 2 h counted outside quiet hours (`addSecondsOutsideQuiet`; actor = the `cleaned_poop` row of the same action, ±5 s); **walk** = the day's goal (`pet_daily_walks`, live `daily_step_count` for the pet's current step day, else the children's `pet_daily_steps`), not on the birth day, not for a past day without step data; done = goal reached (actor = the `walked_pet` row). Order of resolution: done › excused (window overlaps a `pet_status_periods` row and not done → not expected; **the walk — a whole-day routine — only when those periods cover ≥ 50 % of the day's non-quiet time**, `WHOLE_DAY_EXCUSE_SHARE`, so a short or overnight hard stop doesn't excuse it; water is pro-rated instead) › pending (deadline ahead) › missed. A hygiene event still `pending` inside a status period (e.g. after game over — the tick never processes it) is ignored, so it can't keep the day open. Join day: a caretaker who signs mid-day doesn't share that day's water / walk (they open at the day start). Unborn pets and days before `FIRST_LEDGER_DATE` (2026-10-04) have none. Wall clock = family tz, DST-safe (days of 23 / 25 h, instants UTC).
- **Materialisation:** `closeDueDays()` (end of every tick) selects at most `MAX_PETS_PER_TICK` (500) born pets with `routines_next_close_at ≤ now` (or never closed; never-closed and longest-overdue first), computes the days after `routines_closed_through` up to local yesterday (≤ 120 per pass — the backfill of existing pets happens in slices on the first ticks after deploy), stops at the first day that is not final (a pending routine — e.g. a 21:30 mess due 07:30 next morning — or a hygiene event still `pending`), inserts the final days' rows (`insertOrIgnore`) and moves the pointer in one transaction under a `FOR UPDATE` lock on the pet row, only if `routines_closed_through` and `routines_next_close_at` are still the values it read (a concurrent re-activation wins; retried next tick); `routines_next_close_at` = the pending deadline, else the next local midnight; null for an inactive pet whose last closed day was empty (re-activation resets it). A failure for one pet is logged, never stops the tick and pushes that pet's `routines_next_close_at` 30 min ahead (no log flood). Reading (`routinesFor`) = stored rows for closed days + the same computation live for the rest (today), in a constant number of queries for any number of pets and days.
- **Scoring (`CareScoreService`):** pet score = done / expected × 100 − 10 × illnesses (`pet_status_periods` kind illness), clamped 0–100, rounded half up; child score = min(100, done_by_child / fair_expected × 100) − 10 × illnesses since the child started; fair_expected = Σ 1/n over the routines the child shares (n = caretakers whose start ≤ `opens_at`; start = own contract `signed_at`, or `born_at` for grandfathered caretakers); done_by_child = routines whose actor is the child, walk = goal met and the child's steps ≥ goal / n (n = 1 → goal met). Pending routines are not scored; no expected routine → score null; illnesses count from the first ledger day (and the child's start). Traffic light (today, family-local): red = game over › phase 3 (escalation 3) + "fell ill today" (illness period started today); else yellow = > 2 missed routines of today — today's date **or a deadline in (today 00:00, tomorrow 00:00]** (`todayRoutines`, also used by the `today` block) — per child every missed routine they shared; else green. `FamilyDashboardService::family()` builds one board per family (`CareScoreService::board()`), `childReport()` the report.

## 5. Real-time

**Channel (M1-08).** Reverb (`BROADCAST_CONNECTION=reverb`), one event `PetUpdated` (`broadcastAs: pet.updated` — Echo listens to `.pet.updated`) on **`PrivateChannel('pet.{id}')`**, wire name `private-pet.{id}`. No public channels exist.
- **Who may subscribe** (`routes/channels.php` → `PetPolicy@listen`, family model M2-01): **every caretaker child** of the pet (`pet_caretakers`) and **every parent of the pet's family** (`family_user`). A sibling who cares for another pet, a parent or child of another family, a guest, a missing or malformed id → denied. The old `pet.updated.{id}` channel is gone.
- **Auth endpoint:** `POST /api/broadcasting/auth` with `Authorization: Bearer <sanctum token>`, body `socket_id`, `channel_name` (§3). pusher-js calls it on every subscribe through the app's `channelAuthorization.customHandler`.

**Payload** (`PetUpdated::payloadFor`, snapshot taken when the change commits — pet state only, **no child name, email or user id**):
`pet_id, breed_type, hunger_level, thirst_level, energy_level, hygiene_level` (displayed ints) `, is_active, pet_state, escalation_level, is_ill, illness_until (ISO|null), is_game_over, is_hard_stopped, virtual_age_months, born_at (ISO|null), awaiting_contract (M1-07b: true until the first contract is signed; the birth arrives as `event_type: signed_contract` with `awaiting_contract: false`. **Pet-level** — unchanged by M2-01: a child who joined a born pet and hasn't signed sees `false` here; their own lock comes from `GET /api/child/pet` / the 423), current_video_url, media_status, reference_image_url, media (M4-05, signed URLs ≤ 90 min — the channel is private to caretakers + family parents), event_type, updated_at, emitted_at` (ISO, ms — newer wins on the client).
`event_type` values: `metric_changed` (tick, decay catch-up / midnight / recovery side effects), child actions `fed_pet` · `watered_pet` · `walked_pet` · `cleaned_poop` · `signed_contract`, escalation `soft_warning` · `critical_alert` · `parent_intervention_alarm` · `illness_triggered` · `game_over_virtual_shelter` · `escalation_reset`, parent `hard_stop_activated` · `hard_stop_deactivated`, admin `admin_updated` (Filament edit), media `reference_image_ready` (stored on our disk) · `reference_image_failed` · `video_ready` (one per stored state video), purchase `breed_unlocked`.

**Exactly one event per state change.** The single emission point is `PetUpdated::afterCommit($pet, $eventType)`, called by the service that made the change (decay tick, `PetActivityService`, `EscalationService`, hard stop, Filament `EditPet`, fal.ai webhook / job, RevenueCat webhook). There are **no model observers** (`PetObserver` / `ActivityLogObserver` removed): a plain `Pet::save()` or `ActivityLog::create()` broadcasts nothing. Why: the services know which change is meaningful and its type; observers fired on every save, duplicated explicit calls (escalation sent up to 3 events per step) and couldn't name the change. A decay tick that also crosses an escalation threshold sends two events (two state changes: `metric_changed`, then e.g. `soft_warning`).

**Queued, after commit, never fatal (M1-09).**
- `afterCommit` defers to `DB::afterCommit` (and the event also implements `ShouldDispatchAfterCommit`): a rolled-back transaction broadcasts nothing; the snapshot shows committed state.
- `PetUpdated` is `ShouldBroadcast` (not `ShouldBroadcastNow`) with `broadcastQueue = 'broadcasts'`; tries 3, backoff 2 s, timeout 15 s. The tick / request only pushes a `BroadcastEvent` job; the worker talks to Reverb. The job holds no model (snapshot payload), so a deleted pet can't fail it.
- `afterCommit` catches any exception from queueing/broadcasting (logs `PetUpdated: broadcast could not be queued` + `report()`), so a queue or Reverb outage never stops `pets:process-decay` for the remaining pets and never turns a committed child action into a 500.
- Production: dedicated worker `queue-broadcasts` (`queue:work redis --queue=broadcasts`) next to `queue` (`--queue=default`, fal.ai) in `compose.production.yaml` — a slow fal.ai job never delays a broadcast and a Reverb outage never blocks fal.ai. Locally (`QUEUE_CONNECTION=sync`/`database`) run `npm run sail:queue` or the job runs inline.

**Mobile** (`usePetWebSocket` + `src/modules/realtime/echoConfig.ts`): laravel-echo `reverb` with a pusher-js client — `wss` on `EXPO_PUBLIC_REVERB_PORT` (443) with `forceTLS` when the scheme is `https`, `ws` only for local http; `enabledTransports` is **always `['ws', 'wss']`** (with TLS pusher-js 8 only uses the transport *named* `ws`, over `wss://` — `['wss']` alone disabled every transport → `failed`, fixed 2026-10-05); the constructor comes from `resolvePusherConstructor()` because Metro bundles pusher-js' React Native build, which exports `{ Pusher }` without a default (the old `.default` shim threw → permanent `disconnected`, fixed 2026-10-05; regression tests run the real RN build in `pusherReactNative.test.ts`); `echo.private('pet.{id}')`; authorizer = `api.authorizeChannel()` (Bearer token read fresh each subscribe, 401 → session logout handler). `wsStatus` is `connected` only after the channel subscription succeeds (`channel.subscribed`); a subscription error / `unavailable` → `reconnecting`, `disconnected` / `failed` → `disconnected`. The hook drops any event whose `emitted_at` is older than the last one delivered (`createBroadcastGate`) and hands events to a handler: **child HUD** → `applyBroadcastToCache` (TanStack cache `['child','pet']`, M1-13), **parent app (M2-05, PR #20 review)** → `ParentLiveChannels` → `usePetChannels(petIds, handler)`: **one Echo (one websocket) with one private channel per family pet** that is active and not game over, an ordering gate per pet, and a **status per pet**; the store's `wsStatus` is `connected` only while **every** pet channel is subscribed (`aggregateChannelStatus` — one channel failing with 403 keeps polling on even if the others are live). Events go to `modules/family/live.ts#createParentBroadcastHandler`: the event's metrics / flags are patched into that pet of the cached `['parent','dashboard']` at once; any event other than `metric_changed` also invalidates the dashboard, `['parent','activities',petId]` and every `['parent','childReport',…]` (routines, Care Score, light and timeline are server computations); a `metric_changed` tick refetches the dashboard at most once per 60 s (a tick can close a window → missed). The session store is not touched by parent events (`updatePetFromBroadcast` is only the no-handler fallback of `usePetWebSocket`). **Polling:** `useChildPet` refetches `GET /api/child/pet` every 10 s (M1-15) while not connected; `useParentDashboard` every **30 s** while not every pet channel is live, and every **3 min** while live (feed windows / deadlines pass without any event) — both paused in the background via `focusManager`.
- **Ordering on the child:** the cached view remembers `server_time` of the last HTTP snapshot (whole seconds) and `emitted_at` of the last applied broadcast (ms). A broadcast older than either is dropped; a poll that hasn't seen the newest broadcast is dropped when its `server_time` is from an earlier second (`mergePolledState`, run as TanStack `structuralSharing`); action responses always win. A broadcast can't describe feed windows / water / the per-child contract flag, so any event other than `metric_changed`, or one that changes the lock or the mess flag, also triggers a background refetch. The broadcast's pet-level `awaiting_contract: false` never clears the child's own contract flag. A tick that lowers `energy_level` (the family midnight reset) also refetches. A poll older than the shown HTTP snapshot is dropped too.
- **Time-based refresh (PR #18, M3):** no event announces that a feed window opened, the water gap ended or the family day changed, so `useChildPet` keeps one timer for the earliest of `feeding.next_feed_window.start`, `feeding.current_window.end`, `water.next_allowed_at` and the next family midnight (`familyCalendar`), +1 s, then `invalidateQueries(['child','pet'])`; rescheduled on every new state, cleared on unmount. This runs also while the socket is live (polling doesn't). Boundaries are compared in **server time**: each HTTP state stores `clockSkewMs` = `server_time` − device clock on arrival (`nextRefreshDelay`). If a boundary has passed but the state still blocks the action (not because of a lock or mess), it retries every 30 s.

## 9. Production

**Runtime (M4-05b, DEPLOYMENT.md D14):** production image `backend/docker/production/Dockerfile` — `php:8.3-fpm-bookworm` + extensions (pdo_pgsql, pgsql, redis, intl, zip, bcmath, gd, exif, pcntl, opcache), code + `composer install --no-dev --optimize-autoloader` baked in (no bind mount of the code; `composer.lock` changes reach production with the next deploy), non-root uid 1000 (`petprep`, same owner as the `app_storage` files of the Sail era). OPcache on with `validate_timestamps=0` (a deploy recreates the containers), realpath cache 4 MB, FPM `pm=dynamic`, `max_children=12`, `max_requests=500`, `request_terminate_timeout=65s`. `docker/production/entrypoint.sh` builds the Laravel caches **inside each container** on start (`app`: `php artisan optimize` = config, events, routes, views, Filament components + Blade icons; CLI containers: config + events), compiled views in `bootstrap/cache/views` (`VIEW_COMPILED_PATH`) — nothing cache-related on a shared volume any more. The same image runs `app` (php-fpm), `reverb`, `queue`, `queue-broadcasts`, `scheduler`; Caddy runs target `web` (caddy:2.8-alpine + `public/`) and serves `public/` itself (Filament css/js 30 days, `/build` 1 year immutable, zstd/gzip) and `php_fastcgi app:9000` for everything else (`REMOTE_ADDR` = the client Caddy sees, `HTTPS=on` → no proxy headers needed for the app). Fallback for local dev: Sail (`docker/8.5`, `php artisan serve`), unchanged.

Deploy (`scripts/deploy-production.sh`, since M2-01; images since M4-05b): env preflight (before any git/docker call) → record previous release (`repo/.deployed-sha`, tree snapshot in `/opt/petprep/releases/previous`) → **build `petprep-app:next` / `petprep-web:next` from the new tree + smoke test `php artisan optimize` — before maintenance, a failure changes nothing** → **`artisan down`** on the old code (maintenance file on the shared `app_storage` volume: HTTP 503, scheduler and queue workers pause) → DB backup → **code switch** (CI uploads to `/opt/petprep/incoming`, the script rsyncs it into the bind-mounted `repo/`; manual: `git checkout`) → images promoted (`:production` → `:previous`, `:next` → `:production`) → changed Caddyfile validated with the new caddy image (caddy recreated with `--force-recreate` after the migrations — single-file bind mount) → postgres/redis → migrate / seed → recreate containers (per-container caches) → wait for `php-fpm-ping` → `queue:restart` → **`artisan up`** (3 attempts) → health check `/up` end-to-end through Caddy (5 attempts) → prune dangling images. EXIT trap: failure **before** migrations succeeded → code **and images** reverted to the previous release, workers restarted, `artisan up`; failure **after** → release kept (new schema), containers restarted, `artisan up`, loud error. Harness: `scripts/tests/deploy-production.test.sh` (CI job `deploy-script-tests`).

See `docs/PRODUCTION_DEPLOYMENT.md`. Single Hetzner host, Docker Compose: Caddy (`petprep-web`: TLS, static files, pet media) → app (PHP-FPM 8.3, `petprep-app`) / reverb; queue (`default`: fal.ai, media downloads); queue-broadcasts (`broadcasts`: PetUpdated → Reverb, M1-09); scheduler (`schedule:work`); postgres 18; redis. Live at `https://api.petprep.si`.
