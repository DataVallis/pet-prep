## 2. Pravila (tehnično, angleško za kodo)
- **Plan per pet:** `free` (mutt sandbox, forever) or `challenge` (12-week program). Chosen by the parent when creating the pet (dog picker): "Free mutt" or "12-week challenge — 7 days free". Border Collie (premium breeds) only with `challenge`, and **the challenge only with a premium breed** (M5-F03, David 2026-10-07): a new pet with an explicit `plan: challenge` and the mutt (or no breed / no profile → mutt) → 422 `challenge_requires_paid_breed`; an omitted plan (old builds) → `challenge` for a premium breed, `free` for the mutt; a PIN stored before M5-F03 with challenge + mutt (and the deprecated `/child/pair`) creates a free mutt (`PairingService::createPet`). Join / relogin never change the plan.
- **Free plan:** breed mutt only; no "week N of 12", no challenge completion / certificate; parent dashboard history limited to 7 days; basic media tier (static video set). Everything else (needs, actions, steps, escalation, illness, game over, hard stop, quiet hours, training, behaviour) works the same.
- **Challenge status:** `trial` (born, unpaid, now < `trial_ends_at` = birth + 7 days) → `payment_required` (unpaid, now ≥ `trial_ends_at`) → `paid`. Before birth (contract not signed) the trial has not started (`trial_ends_at` null). Paying during the trial → `paid` immediately; the trial is not "extended" (`trial_ends_at` is wall-clock: birth + 7 days).
- **`payment_required` = lock** (new lock reason, like hard stop): decay / escalation / illness counters / training decay paused; child sees a kind locked screen ("Starš mora odkleniti nadaljevanje"); parent sees the paywall for that pet. On payment the pet resumes where it stopped (pause time does not count against needs).
- **Program clock (P9, M3-11b):** time inside `payment_lock` status periods is not program time. The 12-week clock (`virtual_age_months`, `hasReachedSimulationEnd`, certificate), the dog's age / life stage (`LifeStageService`) and the per-child 12-week progress all run from an effective birth = `born_at` + payment-lock seconds before the instant (capped at the lock start while locked). Every lock period counts (trial lock, refund re-lock); admin unlock / purchase closes it. **Lock start** (`payment_locked_at` = period start): an expired trial is locked from `max(born_at, trial_ends_at)` even when the tick runs later (scheduler outage) — that gap is not program time; a refund re-lock starts at the refund (the pet was paid and in play until then). Never before the end of the previous lock, never in the future. Hard stop, illness and inactive periods still count. `born_at` and `trial_ends_at` never change.
- **Credits:** each successful store purchase (RevenueCat NON_RENEWING_PURCHASE / INITIAL_PURCHASE of the consumable, idempotent by event id) creates one **challenge credit** for the buyer's family. A credit is assigned to exactly one pet. Assignment: the app calls `POST /api/parent/pets/{pet}/challenge/activate` after the purchase (idempotent; uses the oldest unassigned credit; 409 `no_credit` if none); the webhook auto-assigns when the family has exactly one unpaid challenge pet. Unassigned credits stay for later pets.
- **Refund** (CANCELLATION of the consumable / REFUND): the credit is revoked; if it was assigned and the challenge is not finished, the pet goes back to `payment_required` (or `trial` if still inside 7 days).
- **Existing pets** (created before this release, testers): `plan = challenge`, status `paid` with source `grandfathered` — nobody gets locked by the deploy.
- **Display (M5-F02, David 2026-10-07: a mutt is never "Paid"):** `plan.display_type` = `free` for a free pet and for a pet of a breed without premium (the mutt) whose challenge is paid but not by a purchase (`grandfathered` / `admin`); else = `type`. Display only — the real plan, program clock, history, certificate and media tier stay unchanged (no data migration). A purchased challenge stays "Paid".
- **Unpaid mutt challenges → free (M5-F02 QA, migration `2026_10_21_120000`):** a mutt with `plan = challenge` and no payment (trial, payment_required, unborn) becomes `plan = free` via `ChallengeService::convertUnpaidMuttToFree` (row lock, non-quiet save): an open payment lock is lifted like a payment (period closed now, thaw, decay clock restart); `pets.converted_to_free_at` keeps its past `payment_lock` periods out of the program clock. No media change, no push.
- **Reminders:** parent push on trial day 6 ("Preizkus se izteče jutri") and when the lock starts (in the device language, M1-18). Child push only "Igra počaka na starša" when locked.
- **Purchases only in the parent app** (password-protected = parental gate); never in a child session.
- **Deletion (P5):** a deleted pet's credit stays used (`challenge_credits.pet_id` → null, `assigned_at` kept). `DELETE /api/parent/children/{child}` and `POST /api/parent/account/delete` (last parent → family) answer 422 `paid_challenge_ack_required` + `pets: [{pet_id, breed_type}]` when a pet they would delete has a challenge paid by a purchase that is neither finished (12 weeks) nor game over, unless the body has `acknowledge_paid_challenge: true`. `GET /api/parent/billing` → `pets[].deletion_loses_purchase`. Admin (Filament) deletions are not gated.
- **AI media (P6):** `full` video set only when `challenge_paid_source = purchase`; trial / payment_required / free / grandfathered → `basic`. Stored videos keep being served (a tier change never deletes or regenerates); a purchase queues the missing full-set videos; after a refund they stay (P10 — no 48 h delay). Stage transitions regenerate only the current tier's set.
- **Trial per child (P7, Claude's interpretation):** a challenge pet's trial is free only if the child signing the first contract has never been a caretaker of another born, non-grandfathered challenge pet; otherwise `trial_ends_at = born_at` (payment_required from birth, lock push with parent copy "no trial"). `POST /api/parent/generate-pin` → `trial_available` (new challenge pet), `GET /api/parent/billing` → `pets[].trial_available`. A game-over pet cannot be activated (422 `pet_not_active`).
